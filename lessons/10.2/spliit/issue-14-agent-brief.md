## Agent Brief

**Category:** bug
**Summary:** Trim group and participant names before validating, so names made only of whitespace are rejected

**Current behavior:**
`groupFormSchema` checks the group name and each participant name only for length (`min(2)` / `max(50)`) and doesn't trim them. So:
- a group name of `"     "` passes. The group is created with no visible name: the Recent groups card is empty and the tab title reads `Expenses ·  · Spliit`.
- a participant name of `"   "` passes.
- participants `"Al"` and `"Al "` are both accepted, because the `duplicateParticipantName` check compares names exactly as typed.
- names are saved with any leading or trailing whitespace the user typed.

The client form (via `zodResolver`), the groups `create` procedure and the groups `update` procedure all use this same schema, so the server accepts these values too. Verified during triage by calling `groupFormSchema.safeParse` on each of the inputs above.

**Desired behavior:**
- Group names and participant names have leading and trailing whitespace removed *before* the length checks. The trimmed value is the one that gets validated and saved.
- A name that is empty, or has fewer than 2 characters, after trimming fails with the existing `min2` message ("Enter at least two characters."), exactly as an empty name does today. This applies to both creating and editing a group, from the form and from the API.
- The duplicate-participant check compares trimmed names, so `"Al"` and `"Al "` are reported as duplicates.

**Key interfaces:**
- `groupFormSchema`: the `name` field and `participants[].name`. Use Zod's `.trim()` (placed before `.min`), so validation and the parsed output both use the trimmed value.
- `GroupFormValues`: the type doesn't change.
- `superRefine` duplicate-name check: receives names that are already trimmed. It shouldn't need its own trimming logic.

**Acceptance criteria:**
- [ ] `groupFormSchema` rejects a group name of only whitespace (e.g. `"     "`) with message `min2`
- [ ] `groupFormSchema` rejects a participant name of only whitespace with message `min2`
- [ ] A name like `" A "` (one character after trimming) is rejected with `min2`
- [ ] A name like `"  Trip  "` is accepted and parses to `"Trip"`; the same goes for participant names
- [ ] Participants `"Al"` and `"Al "` produce a `duplicateParticipantName` issue
- [ ] Unit tests covering all of the above are added next to the existing `src/lib` tests, and the full test suite passes
- [ ] In the UI, submitting the create-group form with a group name of only spaces shows "Enter at least two characters." under "Group name", and no group is created

**Out of scope:**
- **Existing data:** no migration or cleanup of groups or participants already saved with blank or padded names. They stay as they are. (Because of this, editing such a group in settings will now ask the user to fix the name before saving. That's acceptable.)
- **Whitespace inside a name:** repeated spaces between words (e.g. `"A   B"`) are not collapsed. Only leading and trailing whitespace is trimmed.
- Trimming any other field (expense title, group information, currency, etc.)
- Changing the 2 and 50 length limits or the error message text

**References:** Upstream `spliit-app/spliit#704` takes the same approach and can be used as a guide. Note it is still unmerged upstream.
