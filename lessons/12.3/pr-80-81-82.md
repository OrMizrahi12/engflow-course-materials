# PR #80: Refuse a production build GitHub didn't trigger from main

Merge commit: `6beb87f`

## Summary

The build's migrate step now checks where a production build came from before it reads any connection string.

```diff
 vercel buildCommand
   npm run db:migrate            (scripts/migrate.mts)
+    guardProductionBuild(process.env, readCheckoutHead)   (src/db/build-source.ts)
+      not on Vercel, or VERCEL_ENV=preview  -> pass, prints nothing
+      production, GitHub, OrMizrahi12/potluck, main, commit SHA,
+        and checkout HEAD == that SHA       -> pass, prints one line
+      anything else (incl. Vercel with no VERCEL_ENV,
+        no .git, empty variables)            -> throw, naming what it saw
     migrateDatabase(migrationDatabaseUrl())
   npm run build
```

- A CLI upload carries no `.git`, so `vercel deploy -m …` metadata can't pass.
- No GitHub API call and no token. This stops mistakes, not a deliberately faked build.
- `docs/agents/what-stays-human.md`: the migration one-way door now lists `src/db/build-source.ts`. It says the `claude-build.yml` deny for that file hasn't landed yet; that comes in its own PR.

Closes #79

## Evidence

- **Before:** `db:migrate` connected and migrated for any build with `VERCEL_ENV=production`, wherever the build came from.
  **After:** the same run with no Git variables stops before any connection:

  ```text
  $ VERCEL_ENV=production npm run db:migrate
  Error: Refusing this production build: Potluck deploys only from a build GitHub triggered from OrMizrahi12/potluck's main. Nothing was migrated; the current release keeps serving.
  Saw environment: production, provider: (unset), repo: (unset), branch: (unset), commit: (unset), checkout HEAD: <sha>.
  ```

  A GitHub build of `main` whose HEAD matches (run here against the local database):

  ```text
  Production build source check passed: GitHub built OrMizrahi12/potluck's main at c846af2…, and the checkout's HEAD matches.
  Migrations applied and verified.
  ```

- `src/db/build-source.test.ts` (13 tests):

  ```text
  refuses: no Git variables · Vercel with system variables off · no VERCEL_ENV though Git matches main
           another branch · another repo · not GitHub · empty commit · no .git
           no commit and no .git · HEAD != reported commit
  passes:  GitHub build of main, HEAD matches -> returns the log line
  leaves:  preview and local runs -> undefined
  refusal message never contains the connection string
  ```

  For each condition in the check, breaking it on purpose makes at least one test fail. `npm run check` passes: 328 tests.

- **Still for the operator (from #79):** the drill (`vercel deploy --prod --skip-domain` from a laptop checkout fails at this step), and the first real merge after this passing the step. That merge proves `.git` is present in Vercel's Git builds.

## Merge Danger

**Door:** one-way

This changes what runs migrations (`scripts/migrate.mts`), so a human merges it. Auto-merge isn't queued. It adds no migration under `drizzle/`.

**Blast Radius:** releases

If Vercel's GitHub builds turn out to lack `.git` or `git`, or report a variable differently from what the check expects, every production deploy is refused. Nothing is migrated, the current release keeps serving, and new releases are held until this is fixed. The answer is to fix the check, not to add a token. Previews and local runs are unaffected.

# PR #81: Smoke-test each production release and report it on the commit

Merge commit: `397a5c7`

Closes #69, as re-scoped in [the owner's comment](https://github.com/OrMizrahi12/potluck/issues/69): no deployment check and no bypass secret yet. The smoke test reports on the release rather than holding it back.

## Summary

```text
on repository_dispatch vercel.deployment.success, environment = production   (.github/workflows/smoke.yml)
  mark commit "Smoke test" pending
  node scripts/smoke-production.mjs   against https://potluck-zeta.vercel.app
    runSmoke                           (scripts/smoke.mjs)
      until /api/health reports this commit (10 min, every 15 s)
        if it reports a later commit on main (GitHub compare API)
          pass untested: "Not smoke-tested: production moved on to <sha>"
      home page renders              <h1>Potluck</h1>, 200
      made-up /g/<token>             404, "No group at this link" (asks the database)
  mark commit success | failure, with the reason   (always, so it never stays pending)
```

```diff
 GET /api/health
-  { status: "ok" }
+  { status: "ok", commit: VERCEL_GIT_COMMIT_SHA | null }
```

Not here, as the owner decided: the database and schema checks join when #65 lands (which must keep `commit`), and the demo-group check waits for #71. A failure holds nothing back; a person runs `vercel rollback`.

## Evidence

- **Before:** production's `/api/health` answers `{"status":"ok"}`. Nothing checks a release.
  **After:** `scripts/smoke.test.ts` runs `runSmoke` against a local HTTP server:
  ```text
  ✓ passes when the address reports the commit and every page answers
  ✓ waits while the address still reports the previous release
  ✓ fails, saying so, when the address never reports the commit
  ✓ passes untested, at once, when production has moved on to a later commit
  ✓ fails when /api/health never reports the commit within the wait
  ✓ fails when the home page doesn't render
  ✓ fails when a made-up group link doesn't show that there's no group
  ✓ fails, saying so, when the address reports no commit
  ✓ fails, saying so, when nothing answers at the address
  ```
  `health-report.test.ts` covers the commit being present, absent and empty. The full suite passes: 340 tests.
- **Against this worktree's dev server, started with a fake `VERCEL_GIT_COMMIT_SHA`:**
  ```text
  true  | Smoke test passed     (✓ health reports fa1eade… ✓ home ✓ made-up link)
  false | Production never reported 0b9e2c4 within 2s: it still reports fa1eade
  ```
- **Against production today, which predates this change:**
  ```text
  Production never reported 6beb87f within 2s: it reports no commit
  /g/smokeTestNoSuchGroup00 → HTTP 404, "No group at this link"
  ```
- **Not run:** a real Vercel dispatch. GitHub only runs a `repository_dispatch` workflow from `main`.

## Merge Danger

**Door:** two-way, but it adds a workflow under `.github/`, which `docs/agents/what-stays-human.md` lists among the files guarded for settings and secrets. It isn't auto-merged: the owner switches on repository dispatch in Vercel first, then merges.

The workflow gets `statuses: write` and `contents: read`. Payload values reach the shell only through the environment, and the SHA is checked against `^[0-9a-f]{40}$` before any API call. The production address is now written into the repo, which is public.

**Blast Radius:** small

`/api/health` gains a field and the app changes nowhere else. The worst a broken workflow does is post a wrong "Smoke test" status. Don't make that status a required check in "Protect main": it only runs on commits already on `main`, so a PR would wait for it forever.

# PR #82: Fix the smoke workflow's status step so it reports

Merge commit: `1f60b51`

Follow-up to #81 (#69). The smoke test passes, but its status never leaves pending.

## Summary

```diff
 Report the result on the commit
   if OUTCOME is success: state=success, else state=failure
-  description="${SUMMARY:-Smoke test didn't finish: see the run}"
+  description="$SUMMARY"
+  if description is empty
+    description="Smoke test did not finish: see the run"
   gh api …/statuses/$COMMIT  state, description
```

Inside a double-quoted `${…:-word}`, bash reads the `'` in "didn't" as the start of a quoted word and never finds its end. The step died before `gh api` on every run, whether the smoke test passed or failed.

## Evidence

- **Before:** [run 44445737758](https://github.com/OrMizrahi12/potluck/actions/runs/44445737758) on the release of `397a5c7`. The smoke test passed and the report step failed:
  ```text
  ✓ /api/health reports 397a5c728c12163a1b2a309168d1dda8bab29dee
  ✓ the home page renders
  ✓ a made-up group link shows "No group at this link"
  …/7d2e9dd8….sh: line 2: unexpected EOF while looking for matching `''
  ##[error]Process completed with exit code 2.
  ```
  The "Smoke test" status on `397a5c7` stays pending. It's left as it is: the run log is the record.
- **After:** a local check pulled every `run:` block out of `smoke.yml`, ran `bash -n` on each, and ran the report step against a fake `gh` that prints its arguments.
  ```text
  syntax ok: Check the commit / Mark the commit pending / Smoke test / Report the result on the commit
  OUTCOME=success SUMMARY="Smoke test passed"   → state=success  description=Smoke test passed
  OUTCOME=failure SUMMARY="The home page …"     → state=failure  description=The home page answered HTTP 500, not the Potluck page
  OUTCOME=skipped SUMMARY=""                    → state=failure  description=Smoke test did not finish: see the run
  ```
  The same check on `main`'s `smoke.yml` fails with `unexpected EOF`, exit 2, in all three cases.
- **Not run:** a dispatch on GitHub. The next merge's release is the first real run.

## Merge Danger

**Door:** two-way. It touches a file under `.github/`, so it isn't auto-merged; the owner merges it.

**Blast Radius:** none

It changes one step's shell, and only what that step writes into the commit status description.
