  • No more typeof checks inside the schema
  • Server validation becomes testable on its own

3. Give expense writes one module that owns activity, transaction and group scope

Strong local-substitutable (Prisma + test DB)
  • src/lib/api.ts (722 lines, 17 exports, ~26 importers)
  • src/lib/recurrence.ts

Before: each write repeats the same steps by hand

validate participants (copy-pasted :48 / :223)
logActivity, before the write ×6
prisma write, no transaction
where: { id: expenseId }: groupId ignored
recurring link: 3-boolean decision :237

If the write fails, the activity entry is still recorded. Activity logging and deleteExpense have no tests.

After: one thick band

expense writes module

create · update · delete (groupId, expense)

inside: one transaction · activity recorded with the write · scoped to the group · recurring link handled

Problem. Every rule an expense write must follow (record activity, check participants, scope to the group) is repeated by each function in api.ts, and some copies have drifted.

Solution. Make one expense writes module whose small interface carries out all of those rules inside a single transaction.

  • Locality: activity has one source
  • No activity entries for writes that failed
  • Group scope enforced once
  • Tests hit one interface against a real DB
Related to ADR-0001, not in conflict with it: the link is the only access control, but getExpense, updateExpense and deleteExpense ignore groupId. Anyone with one group's link can reach an expense in another group if they know its id, and the activity entry lands in the wrong group. Worth fixing on its own.

4. Make the recurring-frame pass explicit, once per request

Worth exploring local-substitutable

  classDef deep fill:#0f172a,color:#f8fafc,stroke:#0f172a

Problem. Under ADR-0002, frames are created when expenses are read, but the write is buried inside a function named like a plain read. It runs N times for forUser and twice in overview, which already has a comment working around the race.

Solution. Keep create-on-read, but give it its own named step that runs once per request, and fold the pass-through procedures into their routers.

  • Reads become pure and testable
  • The overview race disappears
  • ~15 pass-through files go
Keeps ADR-0002 (frames are created on read, with no scheduler). It changes only how many times and where the pass runs.

Top recommendation

Candidate 1: the expense form model, with candidate 2 in the same piece of work

The expense form is where the history keeps coming back (24 commits), it has no unit tests, and its encoding rules are what make the schema serve two unit systems. Extracting the model creates the seam that the split schemas need, and it fixes the verified amount-limit bug along the way. Separately, the groupId scoping gap from candidate 3 is small enough to fix now.
